# Contributing to RSounds

Thank you for your interest in RSounds.

## Before contributing

1. Check existing issues and pull requests to avoid duplicated work.
2. For a substantial feature, open an issue first to discuss scope and design.
3. Keep changes focused and explain the reason behind them.

## Development principles

- Use Kotlin and follow established Android and Kotlin conventions.
- Prefer small, testable modules with clear responsibilities.
- Keep UI state predictable and accessible.
- Respect Android background execution, audio focus, and media-session requirements.
- Use only authorized APIs and SDKs for online services.
- Do not commit credentials, tokens, private keys, or local machine configuration.

## Pull requests

A pull request should include:

- A concise description of the change.
- Screenshots or a short recording for UI changes, when useful.
- Tests or a clear explanation of how the change was verified.
- Notes about permissions, dependencies, or licensing implications.

## Code of conduct

Be respectful, constructive, and welcoming. Critique ideas and code, not people.
